# Bloomie Days 🌷 — Bouquet Design Studio V2

เกมร้านดอกไม้สามมิติสไตล์ miniature matte clay toy สีพาสเทล สำหรับจัดช่อให้คนพิเศษ ใช้ Three.js และ Vite ฟรีทั้งหมด ไม่มีราคา เงิน ลูกค้า คะแนน เลเวล บัญชีผู้ใช้ หรือ API ภายนอก โมเดลร้าน ฟลอร่า ดอกไม้ กระดาษ และโบว์สร้างด้วยโค้ดต้นฉบับของโปรเจกต์ ฟอนต์บันเดิลในเว็บ

## เล่น V2

1. กด **ยินดีต้อนรับ ร้านเปิดแล้วค่าา** ที่หน้าร้าน ประตูเปิดและกล้องเคลื่อนเข้าไปพบ **ฟลอร่า** แมวเปอร์เซียเพศเมียสีขาวในชุดชมพู
2. ฟลอร่าพูดว่า **สวัสดีนะเมี้ยว~ ตามหาดอกไม้ให้คนพิเศษอยู่ใช่มั้ย? ตามมาเลยเมี้ยวว** เมื่ออ่านจบประมาณ 6.5 วินาที เธอทำท่าชวนตามและกล้องเลื่อนไปด้านข้าง กด **ตามฟลอร่าไปจัดช่อ** เพื่อไปต่อได้เช่นกัน คลังดอกไม้ยังซ่อนจนกล้องถึงจุดหมาย
3. ค้นหาชื่อไทย/อังกฤษจาก **51 ชนิด** แบ่งหน้าครั้งละ 10 รายการ ชี้ภาพเพื่อเห็นชื่อหรือแตะเพื่อเปิดชื่อ ภาพดอกเดี่ยว ความหมาย และคำบรรยาย การเปิดรายละเอียดไม่เพิ่มดอกไม้เอง ต้องกด **+ เพิ่ม** หรือปุ่มเพิ่มในการ์ด
4. ช่อแสดงเป็นวัตถุ 3D จริงตรงกลาง เดสก์ท็อปมีคลังซ้าย/เครื่องมือขวา มือถือมีแท็บด้านล่าง เลือก **ดอกไม้ที่เลือก** เพื่อเพิ่ม/ลดจำนวน เปลี่ยนสี หรือลบชนิด
5. แตะ/คลิกดอกไม้แล้วลากเพื่อย้ายตำแหน่งในระนาบด้านหน้าของช่อ ใช้ช่อง **X / Y / Z**, ปุ่มซ้าย/ขวา/สูง/ต่ำ/หน้า/หลัง หรือสะท้อนซ้าย–ขวาเพื่อปรับละเอียด เลือกก้านจากรายการได้โดยไม่ต้องคลิก 3D ลากพื้นที่ว่าง/ใช้ปุ่มหมุนเพื่อชมช่อ กด **พอดีจอ** คืนมุมพอดี
6. ใน **ทรงและตกแต่ง / ตกแต่งช่อ** เลือกทรงช่อ 6 แบบ กระดาษ 6 ทรง × 10 สี × 4 วัสดุ โบว์ 6 แบบ × 8 สี และเปิด/ปิดไข่มุก ลูกไม้ ใบไม้ ตาข่าย หรือหัวใจ ทั้งหมดเปลี่ยนโมเดลทันที
7. **Undo / Redo** ย้อนการเปลี่ยนทั้งหมด รวมการลากหนึ่งครั้งเป็นหนึ่งขั้น **คืนค่า** คืนรูปทรง/การตกแต่งและจัดสมดุล โดยยังเก็บดอกไม้ จำนวน และสีไว้ การเปลี่ยนทรงช่อจัดตำแหน่งใหม่แต่ไม่ลบดอกไม้
8. บันทึกทุกการเปลี่ยนในเบราว์เซอร์อัตโนมัติ เข้าเกมอีกครั้งแล้วตามฟลอร่าเข้าสตูดิโอเพื่อแก้ช่อเดิม **เริ่มช่อใหม่** มีหน้าต่างยืนยัน เก็บช่อปัจจุบันเป็นช่อก่อนหน้า และ Undo กลับได้ในหน้านี้ เปิดหน้าต่างเดิมแล้วกด **สลับกับช่อก่อนหน้า** เพื่อเรียกคืนแม้โหลดหน้าใหม่แล้ว
9. กด **จัดช่อเสร็จแล้ว ♡** เมื่อมีดอกไม้อย่างน้อยหนึ่งชนิด เพื่อบันทึกช่อสมบูรณ์และชมตัวอย่างหมุนได้ ใช้ **กลับไปแก้ช่อ** เพื่อจัดต่อ

เลือกได้ **15 ชนิด** ไม่ใช่ 15 ก้าน จำกัดชนิดละ **12 ก้าน** และรวม **60 ก้าน** เพื่อช่วยประสิทธิภาพมือถือ เช่น กุหลาบ 5 + ทิวลิป 3 + ลิลลี่แห่งหุบเขา 6 = 3 ชนิด / 14 ก้าน เมื่อครบ 15 ชนิด ปุ่มเพิ่มชนิดที่ 16 จะปิด แต่ยังเพิ่มก้านของชนิดเดิมได้ภายใต้ขีดจำกัด ข้อความภาษาไทยอธิบายเมื่อถึงขีดจำกัด

Lily of the Valley เป็นระฆังสีขาวเล็ก ๆ, Snowdrop มีคอดอกโค้งกับกลีบสีขาวห้อยลง และ Iris มีสามกลีบตั้ง/สามกลีบตกพร้อมแต้มเกสร รูปทรงอื่นแชร์โครงสร้างตามตระกูลและปรับกลีบ เกสร ใบ และพาเลต เป็นการตีความแบบ clay toy ไม่ใช่แบบจำลองทางพฤกษศาสตร์

## เปิดพัฒนาและตรวจสอบ

ต้องมี Node.js **22.12 ขึ้นไป** (ทดสอบด้วย Node.js 24), npm และเบราว์เซอร์ที่รองรับ WebGL 2:

```bash
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดงภายใต้ `/Bloomie-Days-/` ไม่ต้องมี `.env`, secret, database หรือ backend

```bash
npm test
npm run build
npm run preview
```

ผล build อยู่ใน `dist/` ทดสอบ production build ด้วย Playwright ฟรี:

```bash
npx playwright install chromium
npm run test:e2e
# ถ้ามี Chromium ในเครื่อง:
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

ให้ build ก่อน E2E ทุกครั้ง Playwright เปิด preview พอร์ต 4173 ที่ base path จริง ทดสอบเดสก์ท็อป 1440×1000 และมือถือจำลอง 393×873 ด้วย Chromium พร้อมภาพใน `test-results/`:

- Unit tests: ข้อมูล 51 ชนิด/ขยาย 100, ค้นหา/แบ่งหน้า, สถานะกล้อง, แอนิเมชันฟลอร่า, geometry ทุกชนิด, 15 ชนิด/12 ต่อชนิด/60 รวม, ตำแหน่งจริง, หกทรง, Undo/Redo/drag, save/reload/backup, ข้อมูลเสีย/พื้นที่เต็ม และ payload ช่อสมบูรณ์
- Browser tests: หน้าร้านและ intro ปกติ/ลดการเคลื่อนไหว, ชื่อครบทั้งคลัง, รายละเอียดไม่เพิ่มเอง, เมาส์ลาก/สัมผัสลาก, จำนวน/สี/พิกัด, reload, เริ่มใหม่/เรียกช่อเดิม, complete event, ขีดจำกัด, เปรียบเทียบภาพ canvas เมื่อเปลี่ยนทรง/กระดาษ/วัสดุ/โบว์ และ fallback

วิธีตรวจด้วยตนเอง: เล่นตามข้อ 1–9 แล้วลองเพิ่มครบ 15 ชนิด ตรวจว่าชนิดที่ 16 ปิดแต่ชนิดเดิมเพิ่มได้ ลากก้าน เปลี่ยนทรงทุกแบบ เปลี่ยนกระดาษ/วัสดุ/โบว์ ดูผลจริง กด Undo/Redo โหลดหน้าใหม่ และจบช่อ ลองใช้มือถือแนวตั้งและลดการเคลื่อนไหวด้วย

## การบันทึกและส่งต่อเวทมนตร์

LocalStorage ใช้ origin และเบราว์เซอร์เดียวกัน ไม่ส่งข้อมูลออกนอกเครื่อง:

| Key | ข้อมูล |
| --- | --- |
| `bloomie-days:bouquet:v2` | ช่อกำลังแก้: version, IDs, ก้านแต่ละดอก/สี/พิกัด 3D, ทรง, กระดาษ, ริบบิ้น, ของตกแต่ง |
| `bloomie-days:bouquet:previous` | ช่อก่อนหน้า 1 ช่อเมื่อเริ่มใหม่/สลับช่อ; ไฟล์อ่านไม่ได้จะสำรองต้นฉบับก่อนเขียน |
| `bloomie-days:bouquet:finished` | payload ช่อสมบูรณ์ล่าสุด |

จำนวนแต่ละชนิดคำนวณจากก้าน จึงไม่เกิดค่าจำนวนกับโมเดลไม่ตรงกัน ตรวจ schema และขีดจำกัดก่อนโหลด บันทึกเมื่อปล่อยลาก เมื่อพื้นที่เต็ม/บล็อก storage จะแจ้งว่าไม่สำเร็จและเก็บงานในหน้านั้น ไม่อ้างว่าบันทึก/เสร็จแล้ว และไม่เริ่มช่อใหม่หากเก็บสำรองไม่ได้ ประวัติ Undo 50 ขั้นอยู่ในหน่วยความจำของหน้านั้น

เมื่อบันทึกช่อสมบูรณ์สำเร็จจะส่ง event ให้ฉากฟลอร่าเวอร์ชันถัดไป:

```js
window.addEventListener('bloomie:bouquet-ready', ({ detail }) => {
  // detail = { event: 'bloomie:bouquet-ready', version: 2,
  //            completedAt: ISO string, bouquet: editableBouquetDocument }
  // ส่งสำเนาข้อมูลนี้ไปฉากเวทมนตร์ในอนาคต
});
```

V2 ทำเฉพาะสตูดิโอและตัวอย่างช่อสำเร็จ ยังไม่มีฉากเสกเวทมนตร์ editor การ์ด หรือ export PNG/วิดีโอ สัญญาข้อมูลการ์ดและ capability export เดิมยังอยู่ใน `features/keepsakes/model.js` สำหรับต่อยอดด้วย browser APIs ฟรี

## โครงสร้างและประสิทธิภาพ

```text
src/
  main.js                       UI หน้าร้าน/รายละเอียด/เชื่อมสตูดิโอ
  core/{visit,catalog}.js        ลำดับกล้องและค้นหา/แบ่งหน้า
  data/flowers.js                ชนิด ชื่อไทย/อังกฤษ สี ความหมาย คำบรรยาย
  scene/{world,shop,cat}.js       ฉากเดิม ประตู กล้อง และฟลอร่า
  scene/{flowers,clay,optimize}.js โมเดลต้นฉบับ วัสดุ และรวม mesh
  ui/portraits.js                ภาพดอกเดี่ยว lazy cache / SVG fallback
  features/keepsakes/model.js     schema V2, validation, actions, complete payload
  features/bouquet/
    options.js                   รูปแบบและพาเลต
    layout.js                    พิกัดเริ่มต้น 6 ทรง / จำกัดขอบเขต
    store.js                     คำสั่ง Undo/Redo / drag transaction
    storage.js                   อ่าน/บันทึก/สำรองในเครื่อง
    scene.js                     renderer ช่อ, raycasting, fit, lifecycle
    wrapping.js                  กระดาษ โบว์ และของตกแต่ง 3D
    studio.js / studio.css       เครื่องมือและ layout desktop/mobile
```

สตูดิโอสร้าง renderer เมื่อใช้งาน สร้าง prototype เฉพาะดอก/สีที่เลือก แชร์ geometry ระหว่างก้าน รวม mesh ตามวัสดุ และคืน prototype ที่ไม่ใช้แล้ว การเพิ่ม/ย้ายก้านใช้ reconciliation แทนสร้างฉากทั้งหมดใหม่ คืนทรัพยากร/controls/observer/context เมื่อออกจากสตูดิโอ แยกทรัพยากรกระดาษที่สร้างใหม่จากวัสดุ clay ที่ใช้ร่วมกับร้าน

จำกัด pixel ratio และ shadow map, เรนเดอร์เมื่อเปลี่ยนงาน/ระหว่างแอนิเมชันเท่านั้น และหยุดเมื่อแท็บซ่อน ภาพย่อสร้างตามหน้าที่เปิดและมี SVG fallback หากสร้าง context เพิ่มไม่ได้ ใช้ `prefers-reduced-motion` หรือปุ่มบนขวาเพื่อข้ามกล้อง/แอนิเมชัน ไม่ข้าม intro: โหมดนี้รอผู้เล่นกดไปต่อเอง

เพิ่มชนิดใน `src/data/flowers.js` ด้วย `id` ถาวรไม่ซ้ำ ข้อมูลไทย/อังกฤษ/ความหมาย/description, สีและ `form` หากเพิ่มรูปทรงใหม่ให้ขยาย factory และ validator ด้วย คลังไม่กำหนดจำนวนตายตัวและทดสอบการขยาย 100 ชนิดแล้ว

## GitHub Pages และข้อจำกัด

`vite.config.js` ใช้ `base: '/Bloomie-Days-/'` และคง workflow `.github/workflows/deploy.yml` เดิม: เมื่อ merge เข้า `main` จะติดตั้ง dependencies, build และ deploy `dist/` ไป GitHub Pages ฟรี URL: <https://highproidea-creator.github.io/Bloomie-Days-/>

PR นี้ยังไม่ merge จึงยังไม่เปลี่ยนเกมออนไลน์ ต้องตั้ง Settings → Pages → Source เป็น GitHub Actions ไว้ตามการตั้งค่าเดิม ไม่ต้องใช้ token ส่วนตัวในโค้ด

- บันทึกเฉพาะเครื่อง/เบราว์เซอร์เดิม การล้างข้อมูลเว็บไซต์หรือโหมดส่วนตัวอาจทำให้ข้อมูลหาย ช่อก่อนหน้ามีหนึ่งช่อง ไม่ใช่คลังช่อหลายช่อ
- ลากในระนาบ XY และปรับความลึก Z ด้วยเครื่องมือ ระยะถูกจำกัดให้ก้านรวมจุดผูกเสมอ การวางซ้อนกันเองเป็นทางเลือกของผู้เล่น ใช้จัดสมดุลใหม่เพื่อกระจายดอก
- วัสดุโปร่งแสงเป็นการประมาณด้วย Three.js; ไม่มี simulation กระดาษหรือฟิสิกส์ชนกลีบ การจัดวางเริ่มต้นรักษาระยะหัวดอกเหนือขอบกระดาษ
- เครื่อง GPU เก่าอาจช้าหากเลือกช่อใหญ่และของตกแต่งทั้งหมด การทดสอบมือถือเป็น Chromium emulation ยังควรตรวจ Android และ Safari/iOS จริง
- ความหมายดอกไม้เป็นข้อความเชิงสร้างสรรค์สำหรับเกม
